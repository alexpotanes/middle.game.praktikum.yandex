# Переключение темы (8.7)

Доступны светлая (`light`) и тёмная (`dark`) темы. Переключатель в шапке
работает для гостей и авторизованных пользователей. CSS-переменные обновляются
сразу, без перезагрузки страницы; сохранение выполняется через API. При ошибке
сохранения возвращается прежняя палитра и появляется сообщение с предложением
повторить попытку. Цвета находятся в `packages/client/src/styles/theme.ts`.

## Хранение

PostgreSQL 14 запускается существующим Docker Compose. Sequelize использует
постоянный пул соединений. Схема создаётся миграцией
`20260906000000-create-themes.js`, которая также добавляет обе темы.

| Таблица       | Поля и ограничения                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------- |
| `local_users` | `id INTEGER PRIMARY KEY` — ID, полученный сервером из API Практикума                               |
| `site_themes` | `id` — PK; `theme VARCHAR(32)` — уникальный индекс; `description` — название для отображения       |
| `user_themes` | `owner_id` — PK и FK на `local_users.id`; `theme_id` — FK на `site_themes.id` с отдельным индексом |

Все поля обязательны. Первичный ключ `owner_id` гарантирует одну настройку
на аккаунт и индексирует поиск по владельцу. При удалении локального пользователя
настройка удаляется каскадно (`ON DELETE CASCADE`). Удаление используемой темы
запрещено (`RESTRICT`); оба FK имеют `ON UPDATE CASCADE`. Дополнительные индексы,
дублирующие PK или уникальный индекс, не создаются.

Профили и пароли остаются в API Практикума. Локальная запись пользователя содержит
только проверенный ID и создаётся при первом сохранении темы. Сервер проверяет
сессию через `/auth/user`; передать владельца через тело запроса нельзя.
Сохранение локального пользователя и настройки выполняется в одной транзакции
через `upsert`, включая повторные и конкурентные запросы. Получение настройки
использует `INNER JOIN` через Sequelize `include`, без подзапросов.

Гостевой выбор хранится год в cookie `warchest_guest_theme` (`HttpOnly`,
`SameSite=Lax`, `Path=/`, `Secure` при HTTPS-запросе). Для гостя записи в базе
не создаются. Повреждённая cookie или удалённая тема дают светлую тему.

Настройка аккаунта и гостевая cookie независимы: аккаунт без сохранённой настройки
использует `light`, после выхода восстанавливается гостевой выбор. Клиент
загружает тему после проверки сессии и при смене аккаунта. Истёкшая сессия
(`401` от Практикума) обрабатывается как гостевая; сбой проверки сессии даёт
`502` и не сохраняет изменения. Первый SSR-рендер использует светлую палитру;
сохранённая тема применяется после загрузки с клиента.

## API

Маршруты доступны на сервере, по умолчанию `http://localhost:3001`.
Запросы из браузера должны включать `credentials: 'include'`.

| Метод | Маршрут       | Результат                                                                    |
| ----- | ------------- | ---------------------------------------------------------------------------- |
| `GET` | `/themes`     | Массив всех тем                                                              |
| `GET` | `/user/theme` | Текущая тема аккаунта или гостя; `light` по умолчанию                        |
| `PUT` | `/user/theme` | Сохраняет тему, тело строго `{ "theme": "dark" }` или `{ "theme": "light" }` |

Ответ текущей темы и успешного сохранения (`200`):

```json
{ "id": 2, "theme": "dark", "description": "Тёмная" }
```

ID выдаёт база; клиент выбирает тему по имени. Список содержит объекты такого же
формата. Имена тем хранятся строками, без ENUM; при добавлении новой темы в БД
нужно также добавить её палитру и поддержку имени на клиенте.

`GET/PUT /user/theme` возвращают `Cache-Control: no-store`. Неверный JSON,
тип, формат имени или лишние поля дают `400`; неизвестная тема — `404`;
недоступная проверка авторизации — `502`. Ошибки имеют формат
`{ "error": { "code": "...", "message": "..." } }`.

Пример гостевого сценария:

```bash
curl http://localhost:3001/themes
curl -c /tmp/warchest-theme-cookies -X PUT http://localhost:3001/user/theme \
  -H 'Content-Type: application/json' -d '{"theme":"dark"}'
curl -b /tmp/warchest-theme-cookies http://localhost:3001/user/theme
```

Для аккаунта используйте cookie сессии, полученные при входе через существующий
`/auth/signin` или OAuth. Ручки создания и удаления тем публично не предоставляются.

## Запуск и миграции

```bash
docker compose up -d --build
```

При `yarn dev:server`, `yarn workspace server preview` и запуске контейнера
миграции выполняются перед стартом сервера. Выполненные миграции учитываются
в `SequelizeMeta`. Повторный запуск не меняет сохранённые настройки.
Сервер начинает слушать порт только после успешной миграции и подключения к БД.
`sync({ force: true })` и `sync({ alter: true })` не используются.

Ручное применение и откат последней миграции:

```bash
yarn workspace server db:migrate
yarn workspace server db:migrate:undo
```

Откат удаляет три таблицы вместе с настройками; перед откатом остановите сервер.
Параметры подключения берутся из корневого `.env` (`POSTGRES_*`), а в контейнере
из окружения Compose. И применение, и откат схемы выполняются транзакционно.
